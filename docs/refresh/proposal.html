Proposal · September 2026

ChatPRFAQ Frontier Refresh

Rebuild the Working Backwards council on the current Claude platform so the same sequence of colleagues, the same four passes over the press release, and the same human gate produce a document that is deeper, evidenced, faster to watch, and impossible to lose.

Against main, last changed June 2025Owner: Njenga KariukiPrepared with a separate design pass on the council progression and document evolution
01

Summary

The intent was right and the prompts are good. The implementation is a 2025 single-shot pipeline: retired model IDs, no streaming, two seats starved to 500 characters of context, structure recovered from prose by regex, and a run that lives only in one browser tab. The refresh keeps the council and replaces the machinery.

  1. Keep the council and its order. Eleven seats (the original ten plus an optional Bar Raiser), four press-release checkpoints, the human gate after framing. The prompts' craft is ported; their formatting scaffolding is deleted.
  2. Frontier models per seat. Claude Fable 5.1 on the judgment seats, Claude Sonnet 5 on the simple ones, Claude Opus 5 as reviewer and automatic fallback. Adaptive thinking everywhere; effort tuned per seat by an eval.
  3. One frozen council charter as the system prompt, cached for an hour and shared by every step of every run, carrying the whole persona roster so each colleague knows who came before and who comes next.
  4. An append-only dossier in canonical order as the user message, so each seat reads the entire prior context from cache and no persona is ever truncated.
  5. Structured outputs for every seat. The press release is eight typed slots; refinement seats return per-slot edits with rationale and evidence ids; FAQs, findings, hypotheses and insights are fields, not regex targets.
  6. Live research with real citations through Claude's web search and fetch tools, distilled into an evidence ledger that later seats cite by id. Numbers with no finding behind them are flagged as assumptions.
  7. Streaming from the first token, the model's own progress notes replacing the timer-driven "team dynamics" fiction, and reasoning summaries available as working notes.
  8. Persist first, stream second. Every event is logged before it is sent; the stream replays from any point, so refresh, reconnect, share links and history all work and five compensating mechanisms are deleted.
  9. A design built on the eight slots and the roster: handoff connectors, a four-stop version control with a provenance gutter, an edit walkthrough, per-paragraph history, and a tracked-changes Word export attributed to the personas.
  10. Quality made measurable with a Bar Raiser rubric on every run and a twelve-idea eval set graded by an LLM judge.

What was deliberate and must survive

  • Handoffs, not a bag of agents: every prompt is written as "you are receiving X from colleague Y".
  • The press release as a living document with four checkpoints, refined by surgical edits only (preserve paragraph purpose, stay within 10% of word count, add no features).
  • Two simulated customer panels bracketing the drafting: problem validation before v1, concept validation after the VP pass.
  • A single human gate after framing, with per-section feedback.
  • Narration of the team at work while a step runs, and a labelled one-line insight per step (Pain: / Refined: / Risk: / Top Q: / Must nail:).
  • Evidence discipline in the prompts: "do not make up any data", "use language directly from customer research".

What is broken or fragile

  • The insight model was retired in February 2026 and returns 404; the council model is deprecated; the Gemini preview ID is dead.
  • The SDK is pinned two major versions back; temperature and top_p are rejected by current models; 8K max_tokens now caps thinking plus text.
  • Seats 6 and 9 are told to use the problem-validation findings and handed 500 characters of them.
  • PR versions are recovered by regex, with a fallback that stores the whole step output as the version, so v4 can be the entire PRFAQ diffed against a bare press release.
  • A module-level singleton holds run state, so two concurrent users overwrite each other.
  • A debug endpoint returns the first 20 characters of the API key to any caller; reporting and debug routes are unauthenticated; CORS is open.
03

Frontier architecture

The council is a deterministic sequence with typed inputs and outputs per seat, so it belongs on the Claude API as a code-controlled workflow: one Messages request per seat, orchestrated by our own dependency graph. Managed Agents was considered and rejected; it would hand the ordering to the model and the UI to an event stream we do not shape. Every seat is a fresh single-turn request, which also keeps the pipeline clear of Fable 5.1's preserved-thinking history rules.

Facts that shape every call. Thinking is always on for Fable 5.1 (omit the parameter; depth is output_config.effort). No sampling parameters, no prefill, no forced tool choice. max_tokens caps thinking plus text, so size it at 16–32K and always stream. Opt into server-side fallbacks on every call (fallbacks="default" with beta server-side-fallback-2026-07-01) and check stop_reason == "refusal" before reading content. Fable 5.1 requires 30-day data retention on the workspace. Pricing per million tokens: Fable 5.1 $10 in / $50 out with cache reads at $0.25; Opus 5 $5 / $25; Sonnet 5 $2 / $10.

The context system: a cached charter and an append-only dossier

Two rules. The system prompt is frozen for the whole council: the Working Backwards charter plus the full persona roster, marked for a one-hour cache and byte-identical across every seat of every run. The seat's role selection sits at the end of the user message, because changing the system prompt per seat would invalidate the message cache on every step. The dossier is append-only in a canonical order, one text block per artifact, so seat N+1's prompt is seat N's prompt plus new blocks and each seat reads the whole prior context from cache.

Seat 8's prompt. Every block before the task is byte-identical to what seat 7 sent plus the new pr_v3, so it is served from cache. Parallel seats share the prefix: fire seat 5, await its first streamed token, then fire seat 6.

Dependency graph and execution

Seat 7 now also receives the internal FAQ, which the original intended and never wired. Seat 10 reads the evidence ledger and both FAQs alongside the PRFAQ; it could run parallel to seat 9 but ships sequential behind a flag so the "editor waits for everything" beat survives. Critical path: nine stages instead of ten, every one streaming from its first second.

Structured outputs end the regex era

Every seat returns JSON validated against a Pydantic model. The press release is eight typed slots (headline, subheading, summary, problem, solution, benefits, internal quote, call to action), each with its claims tagged as evidence or assumption. Refinement seats return a list of edits (slot, new text, one-sentence rationale, evidence finding ids, change kind) plus the full new version. FAQs, the concept test, hypotheses with numeric ICE fields, and the per-step insight are all fields.

Validation failures retry once with the validator message appended; a seat can no longer silently corrupt the version timeline. Streaming JSON is rendered progressively with a tolerant partial-JSON parser, so the user still watches the PM write paragraph by paragraph.

Research with real evidence

Seat 1 replaces Perplexity with Claude's server-side web search and web fetch in one agentic request (up to fifteen searches), writing research with citations that carry the URL, title and cited passage. Between tool calls, thinking display "updates" returns the model's own progress notes for the UI.

Structured outputs cannot be combined with citations, so seat 1b (Sonnet 5, low effort) turns the cited research into an evidence ledger of findings and sources. From then on every persona cites finding ids for any number or market claim, and the editor flags unsupported quantitative claims as assumptions, which the validation plan picks up. "Do not make up any data" becomes mechanical.

Runtime: persist first, stream second

FastAPI with the async Anthropic client, one task per run, asyncio.gather for the fan-out. Every event the runner emits is appended to an events table before it is pushed; the stream endpoint replays from Last-Event-ID and then tails. A dropped connection, a refresh, a second tab or a shared link all show the same run. Resume re-runs the graph from the last completed seat over the same dossier prefix, with a warm cache. One typed event union, generated into TypeScript, replaces the ad-hoc keys the frontend switches on today.

04

Design direction

Executive-grade and calm: a document tool that happens to show people working, not a dashboard that happens to contain a document. Two ideas are sacred and every screen serves them: a visible progression of colleagues reviewing and handing off, and the press release as a living document whose edits are inspectable, each tied to who made it and what research drove it.

The council progression

A sticky rail lists the roster in fixed order, grouped into four phases (Frame and research; Draft and review; Pressure-test; Refine and finalise). The main column is a timeline of step cards separated by handoff connectors whose labels are generated from the dependency graph, not by a model: every card announces what it read before it wrote. Order is spatial and never changes; when seats 5 and 6 run together, both monograms breathe in their own slots and the top bar reads "2 colleagues working".

The document evolution

A four-stop version control replaces the range slider; each stop carries its author's monogram and the comparative insight as a caption. Three modes: Read, Compare (a redline from one version to another) and Walkthrough (one edit at a time). The unit of change is the slot; inside a changed slot a word-level diff is rendered for reading only. A provenance gutter puts each rationale next to the paragraph it changed, with chips that open the finding and its sources. Any paragraph opens its history across v1 to v4.

Evidence in the executive document

No footnote numbers in the press release by default; Amazon PRs are read as narrative. An Evidence toggle underlines sentences with a linked finding and opens a popover with the claim, the persona who established it, the source and the cited passage. The Research view is the full ledger with backlinks ("used in PR §Problem v2, Internal FAQ Q3"). Simulated panel participants are labelled as simulated wherever they appear.

Visual system

Warm-neutral paper so paper reads as paper, one ink-blue accent for actions and "live", desaturated semantic colours, and a dark theme built from the same tokens. UI in a humanist sans, documents in a text serif at 17px on a 66–72 character measure. Nine recurring colleagues get two-letter monograms in constant-lightness hues that follow them everywhere: rail, card ring, gutter note, Word reviewer colour. No emoji, no shimmer bars, no hover-lift; text appears as it arrives with a single caret.

06

Project outline

Roughly four working weeks for one experienced full-stack engineer, or the owner working with Claude Code, with acceptance criteria per phase. The full outline includes the repository layout, data model, API contract, test strategy and configuration.

Phase 0 · Decide and clear the ground (1–2 days)

Take the decisions below and record them. Confirm the workspace meets Fable 5.1's 30-day retention requirement and check rate limits for Fable 5.x and Opus 5, which are separate buckets. Land groups A and C of the surgical changes on main. Write the twelve seed ideas and freeze the quality rubric. Scaffold the new layout; drop the Gemini, OpenAI, Flask and Gunicorn dependencies.

Done when make dev boots FastAPI and Vite with a health endpoint reporting the three model IDs reachable.

Phase 1 · Council core, backend only (week 1)

Shared schemas and the frozen charter with the roster. The dossier builder with canonical order and cache markers, tested for byte-identical prefixes. The client and stream adapter with fallbacks, refusal handling and usage capture. One seat end-to-end from a command line, then research with web search and the ledger extraction, then every remaining seat ported with the prompt changes. The graph runner with parallel 5 and 6, retries, cancel and resume; the event log and the stream endpoint; Postgres or SQLite through SQLAlchemy.

Done when a full run produces a typed PRFAQ and validation plan with a replayable event log in under six minutes, with cost recorded per seat and an integration test asserting cache reads on seat 3.

Phase 2 · Frontend (week 2)

Design tokens for both themes, the persona identity system and typography. A single reducer over the event union with replay and progressive JSON rendering. The framing review, the council timeline with handoff connectors, working notes and insights, the document views with version stops, redline, provenance gutter, walkthrough and paragraph history, the research ledger, exports (clean and tracked-changes Word, Markdown, PDF), history and share links.

Done when a user can watch a run live, refresh mid-run without losing anything, open it on a phone, step through every edit with its rationale, and export a Word file that matches the old typographic spec.

Phase 3 · Quality, cost, hardening (week 3)

The Bar Raiser seat with rubric scores in the UI. The eval harness with an LLM judge and a hallucination check against the ledger. Effort sweeps per seat and a Fable 5.1 versus Opus 5 comparison on seats 2, 6 and 10. A prompt de-prescription A/B. An ops view for cost, cache hit rate, fallback rate and score trend. Auth, restricted CORS, rate limiting, a Docker image, managed Postgres, a cache pre-warm on boot, and a runbook.

Done when the eval baseline is recorded, the chosen configuration is documented, and production serves a run end-to-end from a fresh deploy.

Phase 4 · Launch and backlog

An optional human gate after v2. "Ask the council" follow-ups over a finished run. Persona memory across a user's runs. Multi-idea comparison, workspaces and comments on sections.
